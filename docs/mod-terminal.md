# The Blueprint mark in Claude Code

[Português](pt-BR/mod-terminal.md)

The `blueprint claude` launcher extracts `blueprint-terminal` and loads it with a second
`--plugin-dir`. The main plugin still provides the skill, the agent, the MCP and the hooks.
The mark does not query the app's data, does not start processes and does not poll.

The mark appears only in a band above the prompt, at any width (decision of
2026-10-23: no side panel). The band's "close ×" button hides it;
`/blueprint-marca` reopens it. Closing keeps the choice for the session, including
across a mod reload. The band shows the image, "The Blueprint" and the short line of
the folder's blueprint.

Raster uses cells with half-height blocks and true colors in any terminal.
Image uses the same PNG in kitty, Ghostty and iTerm2 3.5 or later. The PNG is
16,569 bytes; the grids are 32×16 and 16×8 cells, each cell 12 bytes
(`[glyph, foreground, background]`, u32 little endian). Transparency uses a space or a
lower block, so the transparent background does not turn into a white stroke.

`turn.complete` raises a toast without calling the app. `classic.Notification` raises no toast (decision of 2026-10-22: the notice opened in two corners);
the main plugin's `Notification` hook calls
`blueprint hook notificacao`: it returns a `terminalSequence` with OSC 9, with no control
characters taken from the message. This notice also works without loading the mod; whether it
shows depends on the terminal's notifications being enabled.

## Evidence on 2026-10-22

Local Claude Code: **2.1.309**. The official contracts were read, along with the types
that this version wrote when loading the mod. The API is experimental and may change.

| Check | Result |
| --- | --- |
| `node scripts/marca-terminal.mjs` | PNG and cells generated by Edge, without a window |
| `node scripts/marca-terminal.test.mjs` | PNG signature, limit, asset equivalence and cell size correct |
| `claude plugin validate claude-plugin/plugins/blueprint-terminal` | Passed; editorial warning about the icon for catalog publication |
| `claude plugin test claude-plugin/plugins/blueprint-terminal` | 5 passed: Raster at 100/160 columns, events/toasts, close/reload/reopen and Image in kitty |
| `cargo test hook::tests` | 5 passed, including Notification asking for an answer and the block on escape injection |
| `cargo test cli::claude` | 4 passed, including two `--plugin-dir` and paths with spaces |
| `cargo test registrar::tests::grava_o_plugin` | Full extraction of the assets and Notification passed |

A real interactive session was opened in the agent's PTY with `--plugin-dir`, without
sending a prompt to the model. The mark appeared, `/blueprint-marca` opened the panel and
the debug log confirmed loading and rendering, with no ignored mod hooks. The temporary
log is at `target/mod-terminal-debug.log` (not versioned).

The close test calls the handler with `origin.kind = person` and exercises the
state during a reload and the reopening. The other mod tests use the real host
of `claude plugin test`. The harness API does not expose `$.ui.close` directly.

The checkpoint **"User saw the mark in their own terminal"** is still open:
rendering in the PTY and the tests do not replace the user's own look. Image in
kitty/Ghostty/iTerm2 was validated by the host with a simulated environment, without those
terminals installed on this machine.
